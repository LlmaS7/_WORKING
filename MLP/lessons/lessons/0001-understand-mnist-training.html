1. 先看全局：它究竟在做什么

MNIST 是一个手写数字图片数据集。每张图片只有 28×28 像素，标签是 0～9 中的一个数字。这段程序先给神经网络看训练图片和正确答案，让它调整内部参数；之后再给它没参与参数更新的测试图片，检查识别准确率。

训练不是把图片“存进模型”，而是反复修正一组数字参数，使正确数字对应的输出越来越大。

取数据一次 15 张图
摊平28×28 → 784
预测得到 10 个分数
算损失预测错得多远
反向传播算每个参数的责任
更新参数朝更少犯错移动

训练阶段

模型既预测，也根据错误修改参数。代码中的 loss.backward() 与 optimizer.step() 只出现在这里。

测试阶段

模型只答题，不看答案修改自己。torch.no_grad() 会关闭梯度记录，节省时间和内存。

一次真实运行 当前环境中，这份原始代码从随机参数开始，准确率由 9.11% 上升到 94.63%，第二轮后为 95.84%。结果会随随机初始化和洗牌顺序略有变化；关键现象是训练后准确率显著提高。

2. 先认识四个主角

Tensor（张量）

可以先把它理解为“带形状的多维数字表”。一批图片 x 的形状是 [15, 1, 28, 28]：15 张、1 个灰度通道、每张 28×28。

DataLoader（数据装载器）

它像发牌员，从数据集中取样本、打乱顺序，并每次发出一个 batch。官方教程也把它描述为返回批次的可迭代对象。

Module（模型）

Net 继承 torch.nn.Module。__init__ 声明有哪些层，forward 规定数据如何依次通过这些层。

Optimizer（优化器）

Adam 根据梯度调整模型参数。学习率 0.001 控制每一步调整的大致尺度。

4. 模型：四层“数字加工流水线”

test.py · Net第 8～23 行
class Net(torch.nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = torch.nn.Linear(28*28, 64)
        self.fc2 = torch.nn.Linear(64, 64)
        self.fc3 = torch.nn.Linear(64, 64)
        self.fc4 = torch.nn.Linear(64, 10)

    def forward(self, x):
        x = torch.nn.functional.relu(self.fc1(x))
        x = torch.nn.functional.relu(self.fc2(x))
        x = torch.nn.functional.relu(self.fc3(x))
        x = torch.nn.functional.log_softmax(self.fc4(x), dim=1)
        return x

Linear(784, 64) 到底是什么

一张图被摊平成 784 个像素值。全连接层让每个输出数字都能“查看”全部输入数字，再做加权求和：

输出 = 输入 × 权重 + 偏置

权重和偏置就是模型要学习的参数。第一层有 784×64 + 64 = 50,240 个参数；整个网络共有 59,210 个可训练参数。

位置形状含义
原始 batch[15, 1, 28, 28]15 张灰度图
摊平后[15, 784]每张图变成 784 个像素值
fc1 后[15, 64]每张图变成 64 个特征
fc2/fc3 后[15, 64]继续重组特征
fc4 后[15, 10]每张图对 0～9 的 10 个分数

为什么要有 ReLU

relu(v) = max(0, v)：负数变为 0，正数保留。如果所有层都只有线性变换，多层叠起来仍等价于一层；ReLU 加入“弯折”，让网络能表达更复杂的边界。

最后为什么是 log_softmax

softmax 把 10 个任意分数变成总和为 1 的类别概率；log_softmax 返回这些概率的对数。dim=1 表示：对每一行，也就是每张图片的 10 个类别做转换。

重要配对 原代码的 log_softmax 与后面的 nll_loss 是一对。更常见的简洁写法是让模型直接返回原始分数（logits），再使用 CrossEntropyLoss；官方文档说明它等价于 LogSoftmax + NLLLoss。

5. 数据：从图片文件到批次张量

test.py · get_data_loader第 26～29 行
def get_data_loader(is_train):
    to_tensor = transforms.Compose([transforms.ToTensor()])
    data_set = MNIST("", is_train, transform=to_tensor, download=True)
    return DataLoader(data_set, batch_size=15, shuffle=True)
  1. ToTensor() 把图片转成 PyTorch 张量；灰度值也从整数像素转换到浮点数范围。
  2. MNIST("", is_train, ...) 选择训练集或测试集。空字符串意味着数据根目录依赖程序启动时的当前目录。
  3. batch_size=15 表示每次取 15 张图。它不是训练 15 次，也不是数据集只有 15 张。
  4. shuffle=True 每轮打乱样本顺序。训练集通常需要；测试集不靠顺序计算准确率，因此没必要打乱。

官方 Datasets & DataLoaders 教程把两者分工得很清楚：Dataset 负责单个样本，DataLoader 负责批次、顺序与迭代。

6. 评估：只答题，不学习

test.py · evaluate第 32～43 行
def evaluate(test_data, net):
    n_correct = 0
    n_total = 0
    with torch.no_grad():
        for (x, y) in test_data:
            outputs = net.forward(x.view(-1, 28*28))
            for i, output in enumerate(outputs):
                if torch.argmax(output) == y[i]:
                    n_correct += 1
                n_total += 1
    return n_correct / n_total

x.view(-1, 28*28) 把图片摊平。这里的 -1 不是负数维度，而是让 PyTorch 根据元素总数自动推断 batch 大小，所以结果为 [15, 784]。

argmax 返回 10 个输出中最大值的位置；位置 0～9 正好就是预测数字。最后用“答对数 ÷ 总数”得到准确率。

no_grad() 不等于 eval() no_grad() 关闭梯度记录；model.eval() 则切换 Dropout、BatchNorm 等层的行为。当前网络没有这些层，所以漏掉 eval() 不影响结果，但规范评估代码仍应调用它。

7. 训练循环：真正发生“学习”的五行

test.py · main 中的训练部分第 53～62 行
optimizer = torch.optim.Adam(net.parameters(), lr=0.001)
for epoch in range(2):
    for (x, y) in train_data:
        net.zero_grad()
        output = net.forward(x.view(-1, 28*28))
        loss = torch.nn.functional.nll_loss(output, y)
        loss.backward()
        optimizer.step()
  1. 清空：zero_grad()
    PyTorch 默认会累加梯度。每个 batch 开始前要清空上一个 batch 留下的梯度。
  2. 猜测：output = net(...)
    做一次前向传播，产生每张图对 10 个类别的对数概率。
  3. 打分：loss = nll_loss(output, y)
    查看正确类别的对数概率。正确类别概率越小，损失越大；训练目标是减小损失。
  4. 追责：loss.backward()
    自动求导沿计算过程反向计算：每个参数稍微改变时，损失会怎样变化。这个变化率就是梯度。
  5. 改进：optimizer.step()
    Adam 根据梯度更新 59,210 个参数，使下一次预测有机会更接近答案。
一个 epoch = 把整个训练集完整看一遍；这里训练 2 个 epoch

官方 Optimizing Model Parameters 教程把训练步骤概括为：清梯度、反向传播、优化器更新。你的代码顺序与这个核心闭环一致。

9. 能运行，但还可以写得更稳

下面不是说原代码“错了”，而是展示从教学示例走向常规工程写法时最值得改的地方。

原写法更推荐原因
net.forward(x)net(x)调用 Module.__call__，保留 hook 等框架机制。
net.zero_grad()optimizer.zero_grad()表达“清空这个优化器管理参数的梯度”更直接。
评估时只用 no_grad()加 net.eval()未来加入 Dropout/BatchNorm 后仍能正确评估。
训练前不调用模式训练前 net.train()与评估模式成对，意图明确。
测试集 shuffle=True测试集 shuffle=False准确率不需要打乱，结果展示也更可复现。
LogSoftmax + NLLlogits + CrossEntropyLoss更常见、更简洁，数学上等价。
逐样本 Python 循环计数向量化比较后求和代码更短，也能减少 Python 循环开销。

原代码

可运行
output = net.forward(x)
loss = F.nll_loss(output, y)
net.zero_grad()
loss.backward()
optimizer.step()

常见写法

推荐习惯
logits = net(x)
loss = loss_fn(logits, y)
optimizer.zero_grad()
loss.backward()
optimizer.step()
不要只改损失函数 如果换成 CrossEntropyLoss，模型最后一层就应返回未经 log_softmax 的原始 logits；否则相当于重复处理输出。

10. 从这段代码引出的三条重要知识

知识一：形状是读 PyTorch 代码的导航仪

绝大多数初学错误都能先从形状排查。每经过一层，就问一句：“现在是几张样本？每张有几个特征？”batch 维通常放在最前面，而且不应被意外消掉。

知识二：模型学的是参数，不是 Python 代码

forward() 定义计算规则，在训练时不会被自动改写。真正变化的是每个 Linear 内部的权重与偏置。保存模型，本质上主要是在保存这些参数。

知识三：测试准确率衡量“泛化”

训练集上的高分可能只是记住了见过的样本。测试集不参与参数更新，用它衡量模型对未用于学习的数据是否仍然有效。严格项目通常还会增加验证集，用于选模型和调超参数。

为什么下一步常学 CNN 这里把图片摊平后，像素的上下左右关系不再直接体现在结构中。卷积神经网络（CNN）更擅长利用局部空间结构；但在理解 CNN 之前，先吃透当前训练闭环非常值得。
