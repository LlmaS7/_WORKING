PyTorch 入门 · Lesson 0002

梯度到底是什么？一次参数更新的完整底层过程

不把“反向传播”当成一句魔法口诀：从矩阵乘法、概率与损失开始，手算一个微型网络，再映射回你的 784 → 64 → 64 → 64 → 10 网络。

底层原理 梯度与链式法则 Autograd Adam 约 30 分钟 原代码保持不变

1. 先给结论：网络训练是在解一个数学问题

你的网络里有 59,210 个可调数字，包括四个全连接层的权重和偏置。把这些数字统称为参数，并记作 θ。网络训练的目标不是改写 Python 代码，而是寻找一组更合适的 θ，让训练数据上的平均损失尽可能小。

寻找参数 θ，使平均损失 L(θ) 尽可能小

对一批图片 x，网络先用当前参数作出预测；损失函数把预测和正确答案 y 比较，压缩成一个标量 loss。梯度再回答：“每个参数稍微变化时，loss 会向哪个方向、以多快的速度变化？”优化器利用这个答案修改参数。

参数 θ当前权重与偏置
前向传播矩阵运算得到预测
损失 L预测错得有多严重
梯度 ∇L每个参数的局部影响
优化器把梯度变成更新量
新参数下一批重新计算

梯度不是“错误本身”，也不是“更新后的参数”。它是一张与参数同形状的变化率地图：告诉优化器每个参数往哪里动，会让损失上升或下降得多快。

与上一课的关系 Lesson 0001 解释了整段代码的数据流和张量形状；本课只深挖其中真正发生学习的四行：forward → loss → backward → step。

2. 先分清五类“数字”

类别你的代码中的例子训练时是否被优化器修改
输入数据 图片像素 x，展平后为 [15, 784] 否。它是本次计算的已知条件。
标签 正确数字 y，形状为 [15] 否。它充当答案。
参数 fc1.weight、fc1.bias 等 是。Adam 真正修改的就是它们。
中间结果 每层的加权和、ReLU 输出、logits、对数概率 不会长期保存为学习成果；每次前向传播重新算。
超参数 lr=0.001、batch_size=15、训练 2 个 epoch 否。它们由编程者设定，用来控制训练过程。
最容易混淆的一点 64 是隐藏层宽度，是你选择的网络结构；权重矩阵里的 59,210 个具体数值才是训练过程中自动学习的参数。

3. 这段网络实际用了哪些数学工具

线性代数

向量表示一张图片或一组特征；矩阵同时保存许多神经元的权重；矩阵乘法让一整个 batch 一次完成加权求和。

函数与复合函数

网络是很多函数嵌套：线性层后接 ReLU，再接下一层，最后接 log-softmax 与损失函数。

概率与对数

softmax 把 10 个分数变成总和为 1 的概率；负对数似然惩罚“给正确答案的概率太小”。

微积分

导数和偏导数描述局部变化率；链式法则把每个小运算的局部导数连接成整个网络的梯度。

导数：一个输入的变化率

如果函数只有一个变量，例如 f(w)=w²，导数 df/dw=2w 描述在当前位置附近，w 轻微变化会让 f 大约变化多少。

f(w + Δw) ≈ f(w) + (df/dw) · Δw

例如 w=3 时导数为 6。若 w 增加 0.01，函数值大约增加 6×0.01=0.06。

偏导数：一次只问一个变量

神经网络的损失同时依赖成千上万个参数。∂L/∂w₁ 的问题是：暂时把其他参数固定，只让 w₁ 轻微变化，损失会怎样变化？

梯度：把所有偏导数排成一个整体

∇L(θ) = [ ∂L/∂θ₁, ∂L/∂θ₂, …, ∂L/∂θₙ ]

这里 n=59,210。实际实现不会把所有参数摊成一根长向量；每个参数张量都有一个同形状的 .grad：

参数参数形状梯度形状
fc1.weight[64, 784][64, 784]
fc1.bias[64][64]
fc4.weight[10, 64][10, 64]
梯度的符号怎样读 当 ∂L/∂w > 0，增大 w 会在局部使损失增大，因此想降损失就应减小 w；当梯度小于 0，则通常应增大 w。梯度绝对值越大，表示损失对该参数在当前位置越敏感。

4. 前向传播：从 784 个像素算到 10 个类别

test.py · forward第 17～22 行
def forward(self, x):
    x = torch.nn.functional.relu(self.fc1(x))
    x = torch.nn.functional.relu(self.fc2(x))
    x = torch.nn.functional.relu(self.fc3(x))
    x = torch.nn.functional.log_softmax(self.fc4(x), dim=1)
    return x

一个全连接层究竟计算什么

PyTorch 官方将 Linear 定义为仿射变换：

Y = XWᵀ + b

以第一层为例：

符号形状含义
X[15, 784]15 张图片，每张 784 个像素
W₁[64, 784]64 个神经元各有 784 个权重
b₁[64]64 个神经元各有一个偏置
Z₁=XW₁ᵀ+b₁[15, 64]每张图得到 64 个加权和

偏置 b₁ 会自动广播到 15 行：同一个神经元的偏置用于 batch 中每张图片。

一个神经元就是一次点积再加偏置

zⱼ = x₁wⱼ₁ + x₂wⱼ₂ + … + x₇₈₄wⱼ₇₈₄ + bⱼ

权重决定每个输入像素对该神经元的正负影响和影响强度，偏置则允许判断门槛整体平移。

ReLU 是一个“局部门”

ReLU(z) = max(0, z)

正数通过，负数变成 0。它的局部导数在 z>0 时为 1，在 z<0 时为 0。因此反向传播时，正区间让上游梯度继续通过，负区间会把这条路径的梯度截成 0。

整个前向过程的矩阵表达

A₁=ReLU(XW₁ᵀ+b₁)
A₂=ReLU(A₁W₂ᵀ+b₂)
A₃=ReLU(A₂W₃ᵀ+b₃)
S=A₃W₄ᵀ+b₄

S 的形状是 [15,10]，其中每行是某张图片对数字 0～9 的 10 个原始分数，通常称为 logits。logit 不是概率，可以为负，也不要求总和为 1。

5. 从 logits 到 loss：错误怎样被压缩成一个数

Softmax：把相对分数变成概率

对一张图片的 10 个 logits，softmax 计算：

pᵢ = exp(sᵢ) / Σⱼ exp(sⱼ)

指数保证概率为正，除以总和保证 10 个概率相加为 1。所有类别彼此耦合：提高一个类别的分数，在其他条件不变时会挤压其他类别的概率。

log-softmax：返回概率的对数

log pᵢ = sᵢ − log(Σⱼ exp(sⱼ))

你的网络最后返回 log_softmax 的结果，而不是直接返回概率。使用对数形式有良好的数值稳定性，也让随后计算负对数似然很直接。

NLLLoss：只取正确类别并加负号

如果正确标签是 y，单个样本的损失就是：

ℓ = −log(pᵧ)
模型给正确类别的概率损失 −log(p)含义
0.90约 0.105正确而且自信，惩罚小
0.50约 0.693犹豫不决
0.10约 2.303几乎没把概率给正确答案，惩罚大
0.01约 4.605自信地犯错，惩罚非常大

默认情况下，nll_loss 对 batch 中 15 个样本的损失取平均：

L = (ℓ₁ + ℓ₂ + … + ℓ₁₅) / 15

所以 loss 是一个标量。PyTorch 官方文档说明，常用的 CrossEntropyLoss 在类别标签形式下等价于 LogSoftmax + NLLLoss；你的代码只是把这两步分开写。

为什么需要一个标量 loss 网络有 15×10 个输出，却需要一个统一的优化目标。损失函数把“这一批总体有多糟”汇总成一个数，随后才能求这个数对所有参数的梯度。

6. 手算一次：一个微型网络怎样得到梯度

真实网络有 59,210 个参数，不适合手算。下面缩成“2 个输入 → 1 个 ReLU 神经元 → 2 个类别”，但数学机制完全相同。

已知输入、参数与答案

输入 x = [0.6, 0.2]，正确类别 y = 1
隐藏层 w = [0.5, −1.0]，b = 0.1
输出权重 v₀ = −0.5，v₁ = 1.0

第一步：隐藏层前向计算

z = 0.6×0.5 + 0.2×(−1.0) + 0.1 = 0.2
a = ReLU(z) = 0.2

第二步：得到两个类别的 logits

s₀ = v₀a = −0.5×0.2 = −0.1
s₁ = v₁a = 1.0×0.2 = 0.2

第三步：softmax 与损失

p₀ ≈ 0.4256，p₁ ≈ 0.5744
L = −log(p₁) ≈ 0.5544

正确类别是 1。模型已经稍微偏向类别 1，但只有 57.44% 的把握，所以仍有明显损失。

第四步：先求 loss 对 logits 的梯度

softmax 与负对数似然组合后，有一个非常整洁的结果：

∂L/∂s = p − one_hot(y)

正确标签 y=1 的 one-hot 向量是 [0,1]，因此：

∂L/∂s₀ = 0.4256 − 0 = 0.4256
∂L/∂s₁ = 0.5744 − 1 = −0.4256

这两个符号已经透露了改进方向：类别 0 的 logit 应下降，正确类别 1 的 logit 应上升。

第五步：沿计算链向前追责

要求的梯度链式计算结果
∂L/∂v₀ (∂L/∂s₀)(∂s₀/∂v₀) = 0.4256×a 0.0851
∂L/∂v₁ (∂L/∂s₁)(∂s₁/∂v₁) = −0.4256×a −0.0851
∂L/∂a (∂L/∂s₀)v₀ + (∂L/∂s₁)v₁ −0.6383
∂L/∂z (∂L/∂a)·ReLU′(z)；这里 z>0 −0.6383
∂L/∂w₁ (∂L/∂z)(∂z/∂w₁) = −0.6383×0.6 −0.3830
∂L/∂w₂ (∂L/∂z)(∂z/∂w₂) = −0.6383×0.2 −0.1277
∂L/∂b (∂L/∂z)(∂z/∂b)，而 ∂z/∂b=1 −0.6383

第六步：用最简单的梯度下降更新一次

为了看清方向，暂时不用 Adam，而用学习率 η=0.1 的普通梯度下降：

新参数 = 旧参数 − η × 梯度

输出层

v₀: −0.5000 → −0.5085
v₁: 1.0000 → 1.0085

隐藏层

w₁: 0.5000 → 0.5383
w₂: −1.0000 → −0.9872
b: 0.1000 → 0.1638

用新参数重新前向计算，正确类别 1 的概率约从 57.44% 上升到 60.80%，损失约从 0.5544 下降到 0.4976。这不是保证每一步、每个 batch 都完美下降，而是演示梯度在当前位置确实给出了最陡的局部上升方向，取反后就是局部下降方向。

“追责”只是帮助理解的比喻 梯度不表示某个参数道德意义上“犯了多少错”。它严格表示当前输入、当前标签和当前参数位置下，损失对该参数的局部变化率。

7. 反向传播的数学核心：链式法则

假设损失经过三层函数得到：

L = f₃(f₂(f₁(w)))

那么 w 对最终损失的影响要把沿途每一段的局部变化率相乘：

dL/dw = (dL/df₂) · (df₂/df₁) · (df₁/dw)

在神经网络里，路径会分叉和汇合。一个参数经多条路径影响 loss 时，各条路径贡献还要相加。反向传播并不是另一套独立数学，它是高效组织链式法则的方法：从标量 loss 出发，由后往前复用已经算出的中间梯度。

前向传播

从输入到输出，计算并保存反向阶段需要的中间量，如输入、权重、ReLU 前的值和概率。

反向传播

从 ∂L/∂L=1 开始，把上游梯度乘以每个操作的局部导数，再传给更早的节点。

PyTorch 的官方 Automatic Differentiation 教程说明：autograd 在前向阶段记录运算和对应的梯度函数，调用 backward() 后用链式法则从输出反向传播到叶子参数。

8. 放回真实网络：一层 Linear 的梯度怎样批量计算

不再逐神经元循环。设某层：

Z = AWᵀ + b

其中 A 是这一层的输入，W 和 b 是参数。假设反向传播已经得到上游梯度 GZ = ∂L/∂Z，那么：

∂L/∂W = GZᵀA
∂L/∂b = 对 batch 维求和(GZ)
∂L/∂A = GZW
量第一层形状说明
A[15,784]第一层输入
GZ[15,64]每张图、每个神经元收到的上游梯度
GZᵀA[64,784]恰好与 fc1.weight 同形状
sum(GZ, dim=0)[64]恰好与 fc1.bias 同形状
GZW[15,784]继续向更早的输入传播

ReLU 层怎样反传

GZ = GA ⊙ 1(Z > 0)

⊙ 表示逐元素乘法，1(Z>0) 是掩码：前向时为正的位置取 1，为负的位置取 0。

输出层从哪里开始

对 batch 平均损失，log-softmax 与 NLLLoss 组合后的输出梯度为：

GS = (P − Y) / B

P 是 [15,10] 的概率矩阵，Y 是同形状的 one-hot 标签矩阵，B=15。然后这个梯度依次穿过 fc4 → ReLU → fc3 → ReLU → fc2 → ReLU → fc1，为每层权重与偏置得到梯度。

batch 的梯度是什么 因为默认 loss 是 15 个样本损失的平均值，所以一个参数的最终梯度也是 15 个样本对该参数梯度的平均值。一次 optimizer.step() 使用的是整个 batch 的综合意见。

9. loss.backward() 内部到底做了什么

test.py第 55～57 行
output = net.forward(x.view(-1, 28*28))
loss = torch.nn.functional.nll_loss(output, y)
loss.backward()
  1. 参数已经带有 requires_grad=True
    nn.Linear 创建的权重和偏置是可训练的 Parameter，PyTorch 会追踪由它们参与的计算。
  2. 前向时动态建立计算图
    矩阵乘法、加法、ReLU、log-softmax 和 NLLLoss 都成为图中的操作节点；中间 Tensor 记录创建自己的 grad_fn。
  3. 标量 loss 是图的终点
    调用无参数的 loss.backward()，可理解为从 ∂L/∂L=1 开始反传。
  4. 每个操作执行自己的局部反向规则
    PyTorch 不需要把整个网络化成一条巨型公式；每个操作只需知道如何把收到的上游梯度转换成对自己输入的梯度。
  5. 链式法则一路传到参数
    参数是需要求梯度的叶子节点，结果累加到对应的 parameter.grad。
自动求导不是数值试探 autograd 通常不是把参数加一点、减一点再估计斜率；它依据每个算子的导数规则执行反向模式自动微分。官方的 Autograd mechanics 说明计算图会在每次迭代重新建立。

为什么测试时使用 torch.no_grad()

评估只需要前向结果，不需要随后调用 backward。关闭梯度记录后，不建立这部分反向计算图，可以减少额外内存和计算。它不会让模型“忘掉已经学会的参数”，只是不记录这一次运算历史。

10. 为什么每个 batch 都要清空梯度

test.py第 54 行
net.zero_grad()

PyTorch 的 .grad 默认采用累加语义。连续两次 backward 而不清空时：

grad 中的值 = 第一次梯度 + 第二次梯度

这在某些“梯度累积”训练方法中是有意使用的，但你的代码希望每个 batch 更新一次，因此必须在新 batch 的 backward 之前清掉旧结果。

当前代码

有效
net.zero_grad()
loss.backward()
optimizer.step()

更常见写法

意图更直接
optimizer.zero_grad()
loss.backward()
optimizer.step()

两者在当前代码中都会清除这些网络参数的梯度。官方 优化教程也特别指出：梯度默认会累加，所以每轮更新要显式清零。

11. optimizer.step()：梯度怎样变成参数更新

先理解普通梯度下降

θₙₑw = θₒₗd − η∇L(θₒₗd)

η 是学习率。梯度指向损失上升最快的局部方向，因此前面加负号，沿相反方向尝试降低损失。

梯度与优化器不是同一个东西 loss.backward() 负责计算并存放梯度；optimizer.step() 才读取这些梯度并修改参数。只调用 backward，模型参数不会变化；只调用 step 而没有新梯度，也没有正确的更新依据。

你的代码使用 Adam

test.py第 51 行
optimizer = torch.optim.Adam(net.parameters(), lr=0.001)

Adam 不是简单地给所有参数使用同一个 −lr×gradient 更新量。它为每个参数分别维护两份移动平均：

mₜ = β₁mₜ₋₁ + (1−β₁)gₜ　　梯度的一阶移动平均
vₜ = β₂vₜ₋₁ + (1−β₂)gₜ²　 梯度平方的二阶移动平均

直觉上：

m：方向是否持续

如果最近多批梯度方向一致，更新会更稳定，不会只被某一个 batch 的噪声完全左右。

v：这个参数是否经常剧烈波动

梯度平方长期较大的参数会得到更强的尺度归一化，从而形成逐参数的自适应步幅。

经过初期偏差修正后，Adam 的核心更新可写成：

θₜ = θₜ₋₁ − lr · m̂ₜ / (√v̂ₜ + ε)

你的代码只显式设置了 lr=0.001，其余采用 PyTorch 默认值：β₁=0.9、β₂=0.999、ε=10⁻⁸。ε 防止分母为零并改善数值稳定性。完整算法与参数定义可见官方 Adam 文档。

为什么手算示例先用普通梯度下降 普通梯度下降直接暴露“梯度的负方向降低损失”这个核心。Adam 没有改变梯度的含义，只是在利用历史梯度后更精细地决定每个参数实际走多远。

12. 回到原代码：每个 batch 的完整时间线

    取出 15 个正确类别的负对数概率并求平均，得到标量 loss。

    链式法则从 loss 传回所有层，59,210 个参数分别得到梯度。
  6. Adam 更新参数
    读取当前梯度和历史移动平均，原地修改权重与偏置。
  7. 丢弃本次图，进入下一批
    下一次前向传播会用已经更新后的参数建立一张新计算图。

MNIST 训练集有 60,000 张图片，batch 大小为 15，所以每个 epoch 有：

60,000 ÷ 15 = 4,000 次参数更新

代码训练 2 个 epoch，因此大约执行 8,000 次 backward + step。每次只根据一小批样本估计整个训练集的下降方向，这就是小批量梯度下降的思想；你的实际更新规则是 Adam。

术语准确含义不要误解成

14. 这套解释的边界与三个关键判断

一、梯度是局部信息，不是全局地图

梯度只描述当前位置附近。学习率太大可能一步越过合适区域；损失曲面也可能存在平坦区、鞍点和复杂弯曲，所以“沿负梯度”不等于一步找到全局最优。

二、某个 batch 的 loss 不保证每次都下降

每个 batch 包含不同样本，Adam 还有历史状态。训练中单批损失可能波动；通常观察较长范围的平均损失和独立测试集表现，而不是要求每一步都严格变小。

三、参数更新有效不等于模型真正理解数字

模型学到的是一套把像素映射到类别的数值函数。测试准确率说明它能对未参与本次参数更新的数据泛化到一定程度，但不意味着它具有人的视觉经验和语义理解。

最可靠的心智模型：前向传播算“现在猜什么”，损失把“猜得多差”变成一个数，反向传播算“每个参数对这个差值的局部影响”，优化器再决定“每个参数实际改多少”。
